# 기획 반영 범위와 후속 개발

제공 자료의 공통 화면·1차 MVP를 토대로, 심사 자리에서 연결된 사용자 흐름을 보여주는 웹 시제품을 구현했습니다. 자료의 8주 납품 일정·가격·외주팀 소개는 계약이나 개발 완료 범위로 해석하지 않았습니다.

## 기획 → 구현

| 문서 원칙                  | 현재 구현                                                                              |
| -------------------------- | -------------------------------------------------------------------------------------- |
| 리워드와 성장의 분리       | HC 잔액·거래 원장과 누적 XP 5등급을 분리                                               |
| 건강 행동에 보상           | 걸음 목표 판정, 물 기록, 건강글 확인, 혈압·검사 수치 기록                              |
| 고정 소액 미션·스폰서 재원 | 7,000보 +30 HC/+60 XP, 물 +15 XP, 혈압 +10 HC/+30 XP, 글 +100 HC, 첫 검사 기록 +300 HC |
| 재원별 원장                | 운영사·스폰서·가맹점 구분, 적립·사용 필터와 CSV                                        |
| 중복·오사용 방지           | 일일 미션·글별 보상·쿠폰 중복 차단, 정수·잔액·10% 한도 검사                            |
| 지역에서 먼저 검증         | 효자4·5동을 기본으로 한 동네 설정, 전주천 챌린지, 가상 가맹점                          |
| 의료 신뢰의 표시           | 건강글 출처·작성일·감수 전 상태 표시, 광고 영역 분리                                   |
| 광고와 알선 분리           | 병원 파트너는 월정액 모델 설명, 심의 확인 전 비공개, 전화·웹 버튼 비활성화             |
| 민감정보는 선택            | 명시적 확인 후 기록 기능 활성화, 철회·즉시 삭제, 걷기·가맹점 기능과 분리               |
| 지역 상생의 사업 모델      | HC 경제·소각 여력·성과 퍼널·감수·스폰서·병원 운영 화면                                 |

가맹점·스폰서·참여자 수·주간 그래프·스트릭·운영 KPI는 예시입니다. 명칭이나 숫자는 실재 제휴·실적·감수·승인 상태를 나타내지 않습니다. 병원 심의번호 입력 예시는 서버로 전송하지 않으며 실제 심의 접수가 아닙니다.

## 출시 전에 구현할 핵심

1. 인증·권한: 휴대폰/카카오 인증, 사용자·가맹점·운영자별 서버 권한, 의료광고 검증·공개 게이트.
2. 데이터 기반: 국내 리전 서버·DB, 민감정보 분리·암호화·접근 기록, 보관·파기·동의 이력과 백업 정책.
3. 원장: 서버 트랜잭션, 멱등키, 지급 한도, 스폰서 예산·발행 캡·소각 여력 강제, 유효기간·소멸 관리. 브라우저만의 중복 차단은 보안 경계가 아님.
4. 실제 행동 검증: 건강앱·GPS 연동, 걸음 상한·기기 정책·부정 적립 탐지, 다일 챌린지 집계.
5. 가맹점 사용: 서명·유효기간이 있는 QR, 가맹점 스캔/권한 확인, 사용자 확인, 원장 원자성, 실제 판촉비 내역.
6. 콘텐츠·광고: 의료진 최종 감수, 실제 감수위원·출처·갱신 정책, 광고 심의 증빙과 이해상충 확인, 공개 페이지.
7. 앱 운영: 푸시·알림톡, 네이티브 패키징·스토어 심사, 장애 대응·모니터링, 접근성·실기기 QA.

## 이번 단계에서 제공하지 않는 것

OCR·AI 진단, 실시간 지도·건강 센서, 실결제·현금 교환, 실제 스폰서 집행, 자동 경품 추첨, 상담 DB 수집, 의료기관에서의 HC 사용, 병원 예약 보상은 제공하지 않습니다. 앱 내부에서는 해당 기능을 실제로 수행한다고 표시하지 않습니다.

## 검증 기준

Playwright 테스트로 사용자 행동의 결과를 검증합니다. 목표 전 적립 거부, 하루 한 번 지급·새로고침 유지, 글의 체류·퀴즈·중복 적립, 결제 한도·잔액 초과 거부, 건강 기록 동의·철회·비영속성, 쿠폰 등급·중복 발급, 프로필 저장, 검색·필터, 병원 검증 전 비공개, CSV·초기화 및 모바일 메뉴를 포함합니다. 빌드와 실제 Chromium 실행을 통해 번들·화면·정적 에셋도 확인합니다.

지원사업 자격이나 법적 적합성이 검증된 상태를 의미하지 않습니다. 실제 신청 공고와 출시 전 운영·법무 검토는 별도로 확정할 항목입니다.
