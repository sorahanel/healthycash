# Healthy Cash · 건강 리워드 프로토타입

현직 치과의사의 기획을 바탕으로 **건강 실천 → HC·XP 적립 → 동네 가맹점 사용**을 체험하는 반응형 웹앱입니다. Firebase 회원 인증·프로필 저장과 Netlify 소셜 로그인 서버 함수를 포함합니다. 건강 활동·HC·가맹점·운영 지표는 계속 시연 데이터이며, 실제 결제나 네이티브 앱은 포함하지 않습니다.

제공된 전략기획서·개발로드맵·개발기획서를 기능의 근거로 삼고, HTML 시안 A의 클리닉 그린을 화면 방향으로 선택했습니다. 견적서·회사소개서·포트폴리오는 외주 제안 자료로 참고했으며 계약·결제·제휴나 실적으로 간주하지 않았습니다.

## 실행

Node.js 24와 npm을 사용합니다. 현재 환경에서 Node 24.19.0, Chromium으로 검증했습니다.

```bash
cd /workspace/healthycash
npm ci
npm run dev
```

```bash
npm run build       # TypeScript 확인 + 프로덕션 번들
npm run preview     # 프로덕션 번들 확인
npm test            # Playwright 브라우저 기능 테스트
npm run test:server # OAuth·회원 수정 서버 검증
npm run test:auth   # Java 21 + Firebase 에뮬레이터 권한·로그인 검증
```

테스트는 기본적으로 `/usr/bin/chromium`을 사용합니다. 다른 환경에서는 `CHROMIUM_PATH=/실제/브라우저/경로 npm test`로 지정할 수 있습니다. 테스트 서버는 필요한 경우 자동으로 시작합니다.

## Netlify 배포

GitHub의 `sorahanel/healthycash` 저장소와 `main` 브랜치를 연결합니다. 저장소의 `netlify.toml`이 다음 설정을 지정합니다.

| 설정 | 값 |
| --- | --- |
| Base directory | 저장소 루트 (`.`) |
| Build command | `npm run build` |
| Publish directory | `dist` |
| Node.js | `24` |

원본의 `index.html`은 개발용 `/src/main.tsx`를 참조합니다. 저장소 루트를 그대로 공개하면 브라우저가 TypeScript 앱을 실행하지 못해 빈 화면이 나올 수 있습니다. 빌드를 실행한 뒤 `dist/index.html`과 `dist/assets`를 함께 배포해야 합니다. `dist`는 빌드 중 생성되므로 Git에 올리지 않습니다.

기존 Netlify 사이트는 최신 커밋으로 다시 배포하세요. 자동 배포가 꺼져 있다면 Deploys에서 **Trigger deploy → Deploy site**를 실행합니다. 배포 로그에서 `npm run build`가 성공하고 게시 폴더가 `dist`인지 확인하세요. 회원 로그인을 사용하려면 GitHub 연결 빌드로 서버 함수도 함께 배포해야 합니다. `dist`만 수동 업로드하면 서버 함수가 동작하지 않습니다. 환경변수가 없어도 기존 시연은 사용할 수 있으며, 로그인 버튼은 준비 중으로 표시합니다.

## Firebase · 네이버 · 카카오 로그인

**[콘솔 설정·환경변수·규칙 배포 안내](docs/AUTH_SETUP.md)**를 순서대로 진행하세요. 실제 키는 `.env.example`에 넣지 않고 Netlify 환경변수에 등록합니다.

- 최초 로그인 시 Firebase Auth 회원 및 Firestore `users/{uid}` 생성, 동일 제공자 재로그인 시 동일 계정 유지.
- 마이페이지에서 본인 닉네임·동네 조회/수정, Firebase 로그인 지속 및 로그아웃.
- OAuth state와 브라우저 바인딩 검증, HttpOnly 쿠키와 일회용 교환권, 고정 콜백 주소.
- Firestore는 본인 단건 조회만 허용. 생성·수정은 서버에서 Firebase ID token을 검증한 뒤 수행.
- 기존 HC·XP·건강 기록·시연 프로필은 회원 계정으로 이전하지 않음.

실제 키 설정과 제공자 앱 등록·검수는 별도로 필요합니다. 에뮬레이터 테스트는 실제 제공자 계정 로그인을 대체하지 않습니다.

## 저장 범위

- 마이페이지의 실제 회원 프로필은 Firestore에 저장합니다. 로그인 지속성은 Firebase SDK가 관리합니다.
- **시연용** 닉네임·동네·가상 잔액·활동 원장·쿠폰은 해당 브라우저의 `localStorage`에만 저장합니다. 설정에서 초기화할 수 있습니다.
- 혈압·검사 수치와 건강 기록 동의는 현재 페이지의 메모리에만 보관합니다. 새로고침·동의 철회·초기화 시 삭제됩니다. 원장에는 보상 발생 사실만 남기고 수치는 남기지 않습니다.
- 검사 사진은 실제로 업로드하지 않습니다. 서버·외부 AI로 수치나 사진을 보내지 않습니다.
- 건강 기록과 기존 시연 화면에는 실제 의료 정보를 입력하지 말고 예시 데이터를 사용하세요. 실제 회원정보는 마이페이지에서 관리합니다.

## 실제 출시와 구분할 항목

현재 QR은 `HEALTHYCASH_DEMO_ONLY`라는 시연 데이터만 담고 있습니다. 서버 서명·유효기간·거래 잠금이 없으므로 실제 결제나 인증 수단이 아닙니다. 가맹점·스폰서·쿠폰·심의 상태는 모두 예시입니다. 실제 결제·예약·제휴가 발생하지 않습니다.

휴대폰 본인확인, Apple 건강·삼성헬스, GPS 인증, 가맹점·운영자별 서버 권한, 실제 가맹점 스캔, 서버 원장·트랜잭션·위변조 방지, 발행 캡·잔여 예산 강제, 소멸 배치, 국내 리전 민감정보 저장·암호화, 푸시, OCR, 스토어 패키징·등록은 출시 단계의 별도 구현입니다. 브라우저 저장소의 시연 값은 사용자가 변경할 수 있으므로 금전적 권한을 부여하지 않습니다.

HC 경제 대시보드의 발행 캡·소각 여력·미상환 비율은 운영 모델의 시각화이며 실제 서버 통제가 아닙니다. 챌린지 완주 보상과 경품 추첨은 자동 지급하지 않습니다. 병원은 심의번호 등록 시연 이후에도 비공개 상태를 유지합니다. 실제 광고 공개에는 운영팀의 증빙 확인과 서버 측 게이트가 필요합니다. 건강글은 출처를 표시한 샘플이며 의료진의 최종 감수 완료를 주장하지 않습니다.

## 기술 구성

React 19 + TypeScript + Vite, Firebase SDK/Admin SDK, Netlify Functions, Lucide 아이콘, `qrcode`로 구성했습니다. 로그인·회원 저장은 Firebase와 소셜 제공자 연결을 사용합니다. 외부 지도·광고·분석 SDK·원격 폰트 의존성은 없습니다. 사진·폰트는 사용자가 제공한 HTML의 내장 에셋에서 가져왔고, 구강 건강 일러스트는 프로젝트 내 SVG입니다. 화면은 모바일 하단 메뉴와 PC 사이드바에 대응합니다.

- `src/App.tsx`: 화면·모달·시연 상태와 상호작용
- `src/data.ts`: 예시 데이터, 등급, 날짜, 저장 복원, HC 검증
- `src/style.css`: 반응형 UI
- `src/auth/`: Firebase 로그인 상태·마이페이지
- `netlify/functions/`, `netlify/lib/`: 소셜 로그인 및 회원 수정 서버
- `firestore.rules`: 회원 단건 조회 및 서버 전용 쓰기 정책
- `.env.example`: 공개 웹 설정과 서버 비밀값의 구분
- `tests/app.spec.ts`: 사용자 흐름·중복 보상·결제 한도·기록 삭제·모바일 검증
- [발표용 3분 시연 순서](docs/DEMO.md)
- [기획 반영과 후속 개발 범위](docs/IMPLEMENTATION.md)

검증 명령과 실제 실행 결과·제한은 [검증 결과](docs/VALIDATION.md)를 참고하세요. GitHub Actions에서 빌드·서버·기존 시연·Firebase 에뮬레이터 테스트를 실행하도록 구성했습니다.
