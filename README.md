# Healthy Cash · 건강 리워드 프로토타입

현직 치과의사의 기획을 바탕으로 **건강 실천 → HC·XP 적립 → 동네 가맹점 사용**을 체험하는 반응형 웹앱입니다. 모두의창업 지원사업 발표에서 사용자 가치와 수익 구조를 설명하기 위한 시제품이며, 실제 서비스를 운영하는 서버나 네이티브 앱은 포함하지 않습니다.

제공된 전략기획서·개발로드맵·개발기획서를 기능의 근거로 삼고, HTML 시안 A의 클리닉 그린을 화면 방향으로 선택했습니다. 견적서·회사소개서·포트폴리오는 외주 제안 자료로 참고했으며 계약·결제·제휴나 실적으로 간주하지 않았습니다.

## 실행

Node.js 24와 npm을 사용합니다. 현재 환경에서 Node 24.19.0, Chromium으로 검증했습니다.

```bash
cd /workspace/healthycash
npm ci
npm run dev
```

```bash
npm run build       # TypeScript 확인 + 프로덕션 번들
npm run preview     # 프로덕션 번들 확인
npm test            # Playwright 브라우저 기능 테스트
```

테스트는 기본적으로 `/usr/bin/chromium`을 사용합니다. 다른 환경에서는 `CHROMIUM_PATH=/실제/브라우저/경로 npm test`로 지정할 수 있습니다. 테스트 서버는 필요한 경우 자동으로 시작합니다.

## Netlify 배포

GitHub의 `sorahanel/healthycash` 저장소와 `main` 브랜치를 연결합니다. 저장소의 `netlify.toml`이 다음 설정을 지정합니다.

| 설정 | 값 |
| --- | --- |
| Base directory | 저장소 루트 (`.`) |
| Build command | `npm run build` |
| Publish directory | `dist` |
| Node.js | `24` |

원본의 `index.html`은 개발용 `/src/main.tsx`를 참조합니다. 저장소 루트를 그대로 공개하면 브라우저가 TypeScript 앱을 실행하지 못해 빈 화면이 나올 수 있습니다. 빌드를 실행한 뒤 `dist/index.html`과 `dist/assets`를 함께 배포해야 합니다. `dist`는 빌드 중 생성되므로 Git에 올리지 않습니다.

기존 Netlify 사이트는 최신 커밋으로 다시 배포하세요. 자동 배포가 꺼져 있다면 Deploys에서 **Trigger deploy → Deploy site**를 실행합니다. 배포 로그에서 `npm run build`가 성공하고 게시 폴더가 `dist`인지 확인하세요. 수동 파일 업로드를 사용할 때도 빌드된 `dist` 폴더를 올립니다. 이 시연 앱에는 별도 환경 변수나 API 키가 필요하지 않습니다.

| 영역        | 체험할 수 있는 내용                                                       |
| ----------- | ------------------------------------------------------------------------- |
| 홈          | 오늘의 걸음·HC 잔액·등급·미션·추천 건강글·동네 혜택                       |
| 시작        | 닉네임·동네 설정, 시연 저장 확인, 가입 보상 중복 지급 방지                |
| 미션        | 예시 걸음 추가, 7,000보 도달 판정, 물 기록, 일일 보상 중복 차단           |
| 챌린지      | 스폰서 광고 표시, 참여 등록, 실제 다일 완주 연동과 시연 구분              |
| 건강글      | 3개 글, 분류·검색, 공개 출처, 10초 체류·본문 확인·퀴즈 후 글당 1회 보상   |

| HC 사용     | 가맹점 선택 → 시연 QR → 금액 입력 → 10%·잔액·정수 검증 → 차감·원장 반영   |
| 건강 기록   | 별도 선택 동의, 혈압·LDL·공복혈당 수동 입력, 혈압 추이, 동의 철회·삭제    |

한국 날짜 경계는 `Asia/Seoul` 기준입니다. 일일 미션 상태는 날짜가 바뀌면 초기화하며, 글별 적립·쿠폰 등 일회성 상태는 유지합니다. 5일 스트릭·주간 걸음·랭킹·사업 KPI는 예시로 표시하며 실제 개인·사업 실적이 아닙니다.

## 저장 범위

- 닉네임·동네·가상 잔액·활동 원장·쿠폰은 해당 브라우저의 `localStorage`에만 저장합니다. 설정에서 초기화할 수 있습니다.
- 혈압·검사 수치와 건강 기록 동의는 현재 페이지의 메모리에만 보관합니다. 새로고침·동의 철회·초기화 시 삭제됩니다. 원장에는 보상 발생 사실만 남기고 수치는 남기지 않습니다.
- 검사 사진은 실제로 업로드하지 않습니다. 서버·외부 AI로 수치나 사진을 보내지 않습니다.
- 프로토타입에는 실제 개인·의료 정보를 입력하지 말고 예시 데이터를 사용하세요.

## 실제 출시와 구분할 항목

현재 QR은 `HEALTHYCASH_DEMO_ONLY`라는 시연 데이터만 담고 있습니다. 서버 서명·유효기간·거래 잠금이 없으므로 실제 결제나 인증 수단이 아닙니다. 가맹점·스폰서·쿠폰·심의 상태는 모두 예시입니다. 실제 결제·예약·제휴가 발생하지 않습니다.

휴대폰·카카오 인증, Apple 건강·삼성헬스, GPS 인증, 역할별 서버 인증, 실제 가맹점 스캔, 서버 원장·트랜잭션·위변조 방지, 발행 캡·잔여 예산 강제, 소멸 배치, 국내 리전 민감정보 저장·암호화, 푸시, OCR, 스토어 패키징·등록은 출시 단계의 별도 구현입니다. 브라우저 저장소의 시연 값은 사용자가 변경할 수 있으므로 금전적 권한을 부여하지 않습니다.

HC 경제 대시보드의 발행 캡·소각 여력·미상환 비율은 운영 모델의 시각화이며 실제 서버 통제가 아닙니다. 챌린지 완주 보상과 경품 추첨은 자동 지급하지 않습니다. 병원은 심의번호 등록 시연 이후에도 비공개 상태를 유지합니다. 실제 광고 공개에는 운영팀의 증빙 확인과 서버 측 게이트가 필요합니다. 건강글은 출처를 표시한 샘플이며 의료진의 최종 감수 완료를 주장하지 않습니다.

## 기술 구성

React 19 + TypeScript + Vite, Lucide 아이콘, `qrcode`로 구성했습니다. 런타임의 외부 지도·광고·분석 SDK·원격 폰트 의존성이 없습니다. 사진·폰트는 사용자가 제공한 HTML의 내장 에셋에서 가져왔고, 구강 건강 일러스트는 프로젝트 내 SVG입니다. 화면은 모바일 하단 메뉴와 PC 사이드바에 대응합니다.

- `src/App.tsx`: 화면·모달·시연 상태와 상호작용
- `src/data.ts`: 예시 데이터, 등급, 날짜, 저장 복원, HC 검증
- `src/style.css`: 반응형 UI
- `tests/app.spec.ts`: 사용자 흐름·중복 보상·결제 한도·기록 삭제·모바일 검증
- [발표용 3분 시연 순서](docs/DEMO.md)
- [기획 반영과 후속 개발 범위](docs/IMPLEMENTATION.md)

빌드·기능 검증은 현재 클라우드 인스턴스에서 수행했습니다. 외부 배포, 앱스토어 등록, 환경 발행이나 새 환경 복원 검증은 수행하지 않았습니다.

현재 환경의 `npm run build` 및 Playwright **15개 테스트**가 통과했습니다. [검증 결과](docs/VALIDATION.md)에 검증 범위와 한계를 기록했습니다.
